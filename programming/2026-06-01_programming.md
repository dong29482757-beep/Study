## [C / 재귀 함수] sum(5) 재귀 호출 결과

### 📌 핵심 원리

- 재귀 함수는 **자기 자신을 호출**하며 조건(base case)에 도달할 때까지 스택에 쌓임
- `sum(0)`에서 **`return 0`** 으로 탈출 후, 역순으로 누적 합산
- 호출 구조: `sum(n) = n + sum(n-1)` → **n이 0이면 종료**

### 🏃 손 디버깅 흐름

```c
int sum(int n) {
    if (n == 0) return 0;       // base case: n=0이면 탈출
    return n + sum(n - 1);      // 재귀 호출
}

// sum(5) 호출 스택 전개
sum(5) → 5 + sum(4)
           → 4 + sum(3)
                → 3 + sum(2)
                     → 2 + sum(1)
                          → 1 + sum(0)
                               → return 0   // 탈출
```

| 단계 | 반환값 누적 |
|------|------------|
| sum(0) | **0** |
| sum(1) | 1 + 0 = **1** |
| sum(2) | 2 + 1 = **3** |
| sum(3) | 3 + 3 = **6** |
| sum(4) | 4 + 6 = **10** |
| sum(5) | 5 + 10 = **15** |

### ⭕ 정답

```
15
```

## [C / 포인터] 포인터 변수 연산 결과

### 📌 핵심 원리

- `int *p = &a` → **p는 a의 주소**, `*p`는 **p가 가리키는 값(역참조)**
- `*p`와 `a`는 같은 메모리를 가리키므로 항상 **동일한 값**
- 포인터 역참조(`*p`)는 원본 변수의 값을 직접 읽고 쓸 수 있음

### 🏃 손 디버깅 흐름

```c
int a = 10;
int *p = &a;       // p → a의 주소 저장, *p = 10

int b = *p + a;    // b = 10 + 10 = 20

// 최종 출력 연산
*p + b - a
= 10 + 20 - 10
```

| 변수 | 값 |
|------|----|
| `a` | **10** |
| `*p` | **10** (a와 동일) |
| `b` | **20** |
| `*p + b - a` | 10 + 20 - 10 = **20** |

### ⭕ 정답

```
20
```

## [C / 구조체] 구조체 멤버 접근 및 연산

### 📌 핵심 원리

- `struct` 정의 후 `.` 연산자로 **멤버에 접근**
- 각 구조체 변수는 **독립된 메모리 공간**을 가짐
- 초기화 순서: `{x값, y값}` → 선언 순서대로 매핑

### 🏃 손 디버깅 흐름

```c
struct point {
    int x;
    int y;
};

struct point a = {2, 3};   // a.x = 2, a.y = 3
struct point b = {5, 7};   // b.x = 5, b.y = 7

// 출력 연산
a.x + b.y
= 2 + 7
```

| 변수 | x | y |
|------|---|---|
| `a` | **2** | 3 |
| `b` | 5 | **7** |

### ⭕ 정답

```
9
```

## [Java / 다형성] 메서드 오버라이딩과 동적 바인딩

### 📌 핵심 원리

- `A t = new B()` → **선언 타입은 A, 실제 객체는 B**
- **일반 인스턴스 메서드**는 **런타임(동적 바인딩)** 시 실제 객체 타입 기준으로 실행
- 자식 클래스가 부모 메서드를 **오버라이딩(Override)** 하면, 항상 자식 버전이 호출됨

### 🏃 손 디버깅 흐름

```java
class A {
    String mo() { return "x"; }
}

class B extends A {
    @Override
    String mo() { return "y"; }   // 오버라이딩
}

A t = new B();    // 선언: A, 실제 객체: B
t.mo();           // 런타임 → B의 mo() 호출
```

| 바인딩 시점 | 기준 | 호출 메서드 |
|-------------|------|------------|
| **런타임** | 실제 객체 타입 (B) | **B의 mo() → "y"** |

### ⭕ 정답

```
y
```

## [Java / static] static 메서드 하이딩과 정적 바인딩

### 📌 핵심 원리

- `static` 메서드는 **객체가 아닌 클래스에 귀속** → 런타임 다형성 적용 ❌
- `A t = new B()` 상황에서 `t.nu()` 호출 시 **컴파일 시점(정적 바인딩)** 에 선언 타입 A 기준으로 결정
- 자식 클래스의 동일 이름 static 메서드는 **오버라이딩이 아닌 메서드 하이딩(Method Hiding)**

### 🏃 손 디버깅 흐름

```java
class A {
    static String nu() { return "X"; }   // static → 클래스 A에 고정
    String mo() { return "x"; }
}

class B extends A {
    static String nu() { return "Z"; }   // 하이딩 (오버라이딩 아님!)
    @Override
    String mo() { return "y"; }          // 오버라이딩
}

A t = new B();

t.nu();   // 정적 바인딩 → 선언 타입 A → A의 nu() → "X"
t.mo();   // 동적 바인딩 → 실제 객체 B → B의 mo() → "y"

// 최종 결합
t.nu() + t.mo() = "X" + "y"
```

| 메서드 | 종류 | 바인딩 | 결과 |
|--------|------|--------|------|
| `t.nu()` | static | 컴파일(정적) → **A** | **"X"** |
| `t.mo()` | instance | 런타임(동적) → **B** | **"y"** |

> 💡 **static 메서드는 절대 오버라이딩되지 않는다.** 변수 선언 타입이 항상 우선!

### ⭕ 정답

```
Xy
```
