## [DB / DBMS] DBMS의 3대 필수 기능

### 📌 핵심 원리

- DBMS가 반드시 갖춰야 할 3가지 기능: **정의 · 조작 · 제어**
- 각 기능은 대응되는 데이터 언어(DDL / DML / DCL)와 1:1 매핑됨
- 암기법: **"정조제"**

### 🏃 쿼리 분석

| 기능 | 역할 | 대응 언어 | 명령어 |
|------|------|-----------|--------|
| **정의 기능** (Definition) | 데이터 구조·타입·제약조건 명세 | DDL | `CREATE`, `ALTER`, `DROP` |
| **조작 기능** (Manipulation) | 삽입·삭제·갱신·검색 처리 | DML | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **제어 기능** (Control) | 무결성·보안·권한·병행 제어 보장 | DCL | `GRANT`, `REVOKE`, `COMMIT`, `ROLLBACK` |

### ⭕ 정답

```
정의 기능, 조작 기능, 제어 기능
```

## [DB / 관계형 DB] 관계 데이터베이스 키의 개념

### 📌 핵심 원리

- 키의 두 가지 자격 요건: **유일성**(튜플 구별 가능) / **최소성**(불필요한 속성 없음)
- **슈퍼키** = 유일성 ⭕ 최소성 ❌ → 속성이 과도하게 묶인 상태

### 🏃 쿼리 분석

| 키 종류 | 유일성 | 최소성 | 설명 |
|---------|--------|--------|------|
| **슈퍼키** (Super Key) | ⭕ | ❌ | 튜플 구별만 되면 OK, 불필요한 속성 포함 가능 |
| **후보키** (Candidate Key) | ⭕ | ⭕ | 기본키가 될 자격 있는 정예 멤버 |
| **기본키** (Primary Key) | ⭕ | ⭕ | 후보키 중 대표 선택, NOT NULL + UNIQUE |
| **대체키** (Alternate Key) | ⭕ | ⭕ | 후보키 중 기본키 제외한 나머지 |
| **외래키** (Foreign Key) | - | - | 다른 테이블 기본키 참조, 참조 무결성 보장 |

**💡 관계형 DB 핵심 용어**

| 용어 | 설명 | 대응 개념 |
|------|------|-----------|
| **릴레이션** | 데이터를 표 형태로 표현 | Table |
| **튜플** | 가로 행 | Row / Record |
| **속성** | 세로 열 | Column / Field |
| **카디널리티** | 튜플의 총 개수 | 행 수 |
| **디그리** | 속성의 총 개수 | 열 수 |
| **도메인** | 속성이 가질 수 있는 원자값 범위 | ex) 성별 → '남', '여' |

### ⭕ 정답

```
슈퍼키 (Super Key)
```

## [DB / 이상 현상] 삽입 이상 (Insertion Anomaly)

### 📌 핵심 원리

- **이상 현상(Anomaly)**: 릴레이션 조작 시 데이터 중복으로 발생하는 부작용
- 삽입 이상: 필수 데이터가 없으면 **원하는 데이터 삽입 자체가 불가능**
- 해결책: **정규화(Normalization)** — 테이블을 쪼개서 중복 제거

### 🏃 쿼리 분석

> 사원번호(21067), 이름(세오녀) 입력 시도 → **부서 번호 없음** → 삽입 불가

| 이상 현상 | 발생 상황 | 예시 |
|-----------|-----------|------|
| **삽입 이상** (Insertion) | 불필요한 데이터 없으면 삽입 불가 | 부서 없는 사원 등록 불가 |
| **삭제 이상** (Deletion) | 튜플 삭제 시 유용한 정보도 함께 삭제 | 마지막 수강생 삭제 시 강좌 정보도 소멸 |
| **갱신 이상** (Update) | 중복 데이터 일부만 수정 → 불일치 발생 | 부서명 변경 시 일부 튜플만 반영 |

> 💡 **이상 현상 → 정규화로 해결** 세트로 반드시 기억

### ⭕ 정답

```
삽입 이상 (Insertion Anomaly)
```
